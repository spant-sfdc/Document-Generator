1. Overview & Business Value

DocGen is a 100% Salesforce-native document generation platform. Admins design HTML templates with simple {{token}} placeholders; when a user clicks Generate Document, DocGen pulls live Salesforce data, merges it into the template, and renders a pixel-perfect PDF — entirely inside your org, with no external API calls, no middleware, and no per-document licensing fees.

What DocGen does

  • Merges primary record fields (Opportunity, Account, Contact, custom objects) into an HTML template
  • Traverses parent relationships — e.g. pull Account.Name from an Opportunity record
  • Renders child record tables — e.g. all Opportunity Line Items as repeating rows
  • Evaluates conditional blocks — show/hide template sections based on boolean variables or field-level expressions
  • Injects system values — today's date, logged-in user name, org name, EIN, address, phone, and website
  • Embeds images (logos, signatures) from Salesforce Files as inline base64
  • Renders the final output as a downloadable PDF automatically attached to the originating record

Architecture at a glance

DocGen is fully declarative for end users and administrators. The admin configures a template once through the 5-step visual wizard. End users see a single Generate Document button. They click it and the PDF appears — no code, no configuration, no waiting.

Salesforce-native security All data access runs through standard SOQL with WITH SECURITY_ENFORCED. DocGen fully respects field-level security, sharing rules, and permission sets — exactly like any native Salesforce Apex class.

2. Admin Configuration Workflow

The DocGen Template Builder is a 5-step wizard accessible from the DocGen app in the App Launcher, or directly via the Document Generator tab. Complete all steps in order; the wizard preserves state between steps.

Step 1 — Upload Template

  1. Open the DocGen app → Template Builder
    Launch the DocGen app from the App Launcher and click New Template.
  2. Upload your HTML file
    Drag-and-drop or browse to select your .html template file. Max size: 5 MB. The file is stored as a Salesforce ContentVersion record — no external storage.
  3. Review extracted tokens
    DocGen immediately parses the HTML and lists every {{token}} it finds. Verify the list matches your template design before proceeding.
Template authoring tip Write templates in any HTML editor. Use {{TokenName}} anywhere in the body. For child tables, wrap a <tr> between {{#RelationshipName}} and {{/RelationshipName}}. For conditional sections use {{#if variableName}}...{{/if}}. Keep all CSS inline or in a <style> block — external stylesheets are not fetched by the PDF renderer.

Step 2 — Select Primary Object

  1. Search for the source object
    Type a label or API name. Results include all accessible standard and custom objects. Select the object whose record page will host the Generate Document button.
  2. Confirm selection
    The wizard displays the object label and API name. Click Next to proceed to mapping.

Step 3 — Map Tokens

For each {{token}} in the template, define where its value comes from.

Auto-fill

Click Auto-fill Mappings. DocGen matches every token whose name exactly matches a field API name on the primary object (case-insensitive). Parent traversal tokens such as {{Account.Name}} are also resolved automatically in this step.

Manual mapping types

TypeWhen to useWhat to configure
FieldToken maps to a single field on the primary or a parent objectSelect object → select field. Use the relationship picker if the primary object has multiple lookups to the same parent.
ConstantToken always renders the same static textType the static value directly.
RepeatingToken is inside a child section blockSelect the child object and the field within it. Ensure Is Repeating is checked.
Child section tokens must be mapped as Repeating Tokens inside {{#RelationshipName}}...{{/RelationshipName}} must have their mapping type set to Repeating with the correct child SObject selected. If mapped as a primary field, they will render blank.

Step 4 — Configure Variables

Variables are named values resolved independently of token-to-field mappings. They power conditional blocks and expose org-level information without hardcoding it in the template.

TypeDescriptionUse case
Text / Number / DateStatic constant at runtimeProposal reference numbers, static labels
System DateToday's date in org default formatDocument generation date
Current UserFull name of the logged-in userPrepared by / Account Manager
Org NameOrg display name from DocGen Config CMT or UserInfoLetterhead org name

Expression syntax Supported operators: > < >= <= == !=. Left-hand side must be a field API name on the primary object. Right-hand side is a literal value or null.

Examples: Amount > 10000 · StageName == 'Closed Won' · Total_Donation__c != null

Step 5 — Preview & Save

  1. Enter a test Record ID
    Paste the 18-character Salesforce ID of a real record. The wizard fetches live data from that record for the preview.
  2. Click Preview
    DocGen merges the template with live data and renders an HTML preview in-browser. Verify all tokens resolved, child tables expanded, and conditional blocks toggled correctly.
  3. Click Save Template
    The wizard saves the full configuration (mappings + variables) as a JSON blob attached to the ContentVersion. The template is now ready for end-user generation on any record of the configured object.

3. End User Flow — Generate a Document

Once an admin has configured a template, generating a document requires no training and takes under 30 seconds.

  1. Open the record
    Navigate to any Salesforce record of the object the template is configured for (e.g. an Opportunity record).
  2. Click Generate Document
    Find the button in the record's action bar or on the DocGen component on the page layout.
  3. Select the template
    A dropdown lists all templates configured for this object. Select the one you want.
  4. Click Generate
    A progress bar displays while DocGen fetches data, merges the template, and renders the PDF. Typical time: under 3 seconds.
  5. Preview the PDF
    The PDF renders inline in the modal. Scroll through to verify the content before downloading.
  6. Download
    Click Download PDF. The file saves to your downloads folder and is simultaneously attached to the record as a Salesforce File.
Generated PDFs are automatically attached to the record Find them in the record's Files related list. File name format: [TemplateName] – [RecordName] – [Date].pdf.

4. Template Token Reference

Tokens are placeholders enclosed in double curly braces: {{TokenName}}. DocGen supports four token categories.

{{FieldName}}
Primary object field. Auto-resolved if the token name matches the field API name (case-insensitive).
{{Relationship.FieldName}}
Parent traversal — single hop. Examples: {{Account.Name}}, {{Owner.Email}}.
{{#RelName}} ... {{/RelName}}
Child repeating section. Everything between the tags renders once per child record.
{{sys.variableName}}
System or admin-defined variable resolved by the Variable Engine before field merging.

System variables — always available

TokenResolved value
{{sys.today}}Current date in org default format
{{sys.currentUser}}Full name of the logged-in user
{{sys.userEmail}}Email address of the logged-in user
{{sys.orgName}}Org display name (DocGen Config CMT or UserInfo fallback)
{{sys.orgEIN}}Organisation EIN from DocGen Config CMT
{{sys.orgAddress}}Organisation address from DocGen Config CMT
{{sys.orgPhone}}Organisation phone from DocGen Config CMT
{{sys.orgWebsite}}Organisation website from DocGen Config CMT

Complete template example — Donation Proposal

<!DOCTYPE html>
<html>
<head><style>
  body { font-family: Arial, sans-serif; padding: 40px; }
  table { width: 100%; border-collapse: collapse; }
  th, td { border: 1px solid #ccc; padding: 8px; }
  .badge { background: #032d60; color: #fff; padding: 4px 10px; border-radius: 4px; }
</style></head>
<body>
  <h1>Donation Proposal — {{Name}}</h1>
  <p>Prepared for: <strong>{{Account.Name}}</strong></p>
  <p>Date: {{sys.today}} | Campaign: {{Campaign_Name__c}}</p>
  <p>Donation Type: {{Donation_Type__c}}</p>

  <h2>Contribution Breakdown</h2>
  <table>
    <tr><th>Programme</th><th>Amount</th></tr>
    {{#OpportunityLineItems}}
    <tr>
      <td>{{Contribution_Type__c}}</td>
      <td>{{TotalPrice}}</td>
    </tr>
    {{/OpportunityLineItems}}
  </table>

  {{#if isMajorDonor}}
  <div class="badge">Major Donor — Recognition Level: Platinum</div>
  <p>Thank you for your exceptional generosity.</p>
  {{/if}}

  <p>Prepared by: {{sys.currentUser}}</p>
  <p>{{sys.orgName}} | {{sys.orgAddress}}</p>
</body>
</html>

5. Variables & Conditional Rendering

How variables work

Variables are resolved by the Variable Engine before the template merges with field data. Each variable has a name and a type. The resolved value is injected wherever {{variableName}} or {{sys.variableName}} appears in the template.

Expression variables

An EXPRESSION variable evaluates a field comparison against live record data at generation time. The result is always true or false, making it the primary mechanism for conditional sections.

ExpressionEvaluates to true when…
Amount > 10000Opportunity Amount exceeds $10,000
Amount >= 71000Amount is $71,000 or more
StageName == 'Closed Won'Stage is exactly "Closed Won"
Total_Donation__c != nullTotal Donation field has any value
Donor_Type__c == 'Foundation'Donor type picklist is "Foundation"

Conditional blocks

Use {{#if variableName}}...{{/if}} to show or hide any block of HTML based on a variable's resolved value. The block renders only when the variable is truthy (true, a non-empty string, or a non-zero number).

{{#if isMajorDonor}}
<div style="background:#e8f4fd; padding:12px; border-left:4px solid #032d60;">
  <strong>Major Donor — Recognition Level: Platinum</strong>
  <p>This gift qualifies for the Major Donor Recognition Programme.</p>
</div>
{{/if}}
Multiple independent conditions are supported Each {{#if}} block is evaluated independently. A single template can contain multiple conditional sections each driven by a different variable.

Image variables

Create an IMAGE variable, paste the ContentVersion ID of the uploaded file, and place {{variableName}} in the template. DocGen base64-encodes the file and renders an inline <img> tag. No external URLs or CDN required.

6. Parent / Child Mapping

Parent traversal

DocGen supports single-hop parent traversal. Token {{Account.Name}} on an Opportunity template will query Account.Name via the AccountId lookup — automatically, with no extra SOQL needed from the admin.

If the primary object has multiple lookups to the same parent (e.g. two Account lookups on a custom object), the mapping builder shows a relationship picker so you select the correct relationship.

Supported parent traversal examples

TokenPrimary objectSource
{{Account.Name}}OpportunityAccount.Name via AccountId
{{Account.BillingCity}}OpportunityAccount.BillingCity
{{Account.Donor_Type__c}}OpportunityCustom field on Account
{{Account.Website}}OpportunityAccount.Website
{{Owner.Name}}AnyUser.Name via OwnerId
{{Owner.Email}}AnyUser.Email via OwnerId

Child record tables

Wrap any repeating HTML block with the child relationship open and close tags. Everything inside renders once per child record.

<table>
  <thead>
    <tr><th>Programme</th><th>Quantity</th><th>Amount</th></tr>
  </thead>
  <tbody>
    {{#OpportunityLineItems}}
    <tr>
      <td>{{Contribution_Type__c}}</td>
      <td>{{Quantity}}</td>
      <td>{{TotalPrice}}</td>
    </tr>
    {{/OpportunityLineItems}}
  </tbody>
</table>

7. Format Overrides

Each field mapping in the builder has an optional Format Override. This controls how the raw Salesforce value is displayed in the rendered document, without modifying the underlying data.

Format stringEffectExample output
currencyPrefixes with $, formats to 2 decimal places$71,000.00
date:MM/dd/yyyyFormats a date using Java date pattern09/30/2026
date:MMMM d, yyyyLong-form dateSeptember 30, 2026
date:dd MMM yyyyEuropean/UK format30 Sep 2026
number:2Rounds to N decimal places71000.00
upperConverts to UPPERCASEFOUNDATION
lowerConverts to lowercasefoundation
Format overrides are per-mapping The same field can appear multiple times in a template with different token names, each configured with a different format override.

8. Troubleshooting

Token renders blank in the PDF

  • Open Template Builder → Mappings tab and verify the token has a mapping configured.
  • Check that the mapped field has a non-null value on the test record used in Preview.
  • If the token is inside a child section, confirm the mapping type is Repeating with the correct child object selected.
  • Run Auto-fill — if the token name does not match any field API name it cannot be auto-resolved and must be mapped manually.

Child table does not render or is empty

  • Confirm the relationship name in the template (e.g. {{#OpportunityLineItems}}) matches the Salesforce child relationship name (case-insensitive).
  • Ensure child records exist for the test Record ID used in the Preview step.
  • Verify the running user has Read access to the child object and all mapped fields (FLS).
  • Check Max_Repeating_Rows__c in the DocGen Config CMT — if set to 0, no rows are returned.

Conditional block is not showing

  • Confirm the variable name in {{#if variableName}} exactly matches the variable name configured in Step 4 — this is case-sensitive.
  • For EXPRESSION variables, verify the field API name (left-hand side) exists on the primary object and is accessible to the running user via FLS.
  • Use the Preview step to inspect what value the variable resolved to before saving.

Permission / access errors on generation

  • Assign DocGen_Full_Access permission set to the running user for full wizard and generation access.
  • Assign DocGen_Demo_Fields permission set to grant FLS on the demo custom fields (Donor_ID__c, Donor_Type__c, Campaign_Name__c, Donation_Type__c, Total_Donation__c, Is_Major_Donor__c, Contribution_Type__c).
  • DocGen uses WITH SECURITY_ENFORCED on all SOQL. If a mapped field is inaccessible to the user, the query will throw a QueryException. Grant FLS via profile or permission set.

Template upload fails

  • Confirm the file is valid UTF-8 encoded HTML (not a Word document, PDF, or binary file).
  • File size must be under 5 MB.
  • The running user needs Create permission on ContentVersion — included in DocGen_Full_Access.

PDF has no styling / looks unstyled

  • DocGen renders HTML through the Salesforce Visualforce PDF renderer. Inline CSS (style="" attributes) and <style> blocks in the <head> are fully supported.
  • External stylesheet URLs (CDN links, Google Fonts) are not fetched by the renderer. Embed all styles inline.
  • Complex CSS (flexbox, grid) may not be fully supported by the PDF renderer — use table-based layouts for reliable cross-page formatting.

Mapping mismatch — wrong field value appears

  • In the mapping builder, verify the Source Object and Source Field for each token. A common mistake is mapping a child-section token to a primary object field.
  • For parent traversal tokens (e.g. {{Account.Name}}), ensure the Relationship Path field is set to Account.Name, not just Name.
